# 이슈 7: 저장 프롬프트 계획

## 목표

로그인한 사용자가 본인 프롬프트를 최대 5개 저장하고, 번호 생성 화면에서 저장한 프롬프트나 새 의견을 골라 사용할 수 있게 한다. 프롬프트 데이터는 MongoDB에 사용자별로 저장해 다른 기기에서도 동기화한다.

## 확정된 동작

- 저장 프롬프트는 제목과 내용으로 구성한다.
- 저장·수정·삭제는 생성 화면의 `프롬프트 관리` 다이얼로그에서 한다.
- 생성 화면에서 저장 프롬프트 선택과 새 의견 입력은 동시에 적용하지 않는다.
- 둘 다 선택하지 않으면 기존 기본 프롬프트를 적용한다.
- 5개가 저장된 상태에서 추가 저장을 요청하면 생성하지 않고 이유를 안내한다.
- 모든 읽기·쓰기 API는 세션에서 확인한 사용자 ID로 범위를 제한한다.
- 제목은 최대 30자, 내용은 최대 300자다.
- 사용자별 TanStack Query 캐시 키를 사용하고 저장·수정·삭제 후 갱신한다.

## 구현 작업

### Task 1: 저장 프롬프트 모델과 입력 검증

- `SavedPromptDocumentSchema`를 `title`·`content` 구조로 바꾸고 제목 30자, 내용 300자 제한을 적용한다.
- 생성·수정 입력과 클라이언트 응답용 타입을 정의한다. 응답에는 내부 MongoDB 문서 형식 대신 문자열 ID와 ISO 시각을 반환한다.
- 문서 및 입력 스키마 테스트에서 필수값, 공백, 최대 길이 경계, 유효하지 않은 ObjectId를 검증한다.

### Task 2: 사용자 범위 저장소

- 목록·생성·수정·삭제 함수를 `src/entities/saved-prompt/server/`에 둔다.
- 모든 MongoDB 쿼리에 현재 세션의 `userId`를 조건으로 넣는다.
- `sortOrder`를 0~4 슬롯으로 사용하고 `{ userId, sortOrder }` 고유 인덱스와 충돌 재시도로 동시 저장에서도 최대 5개를 지킨다. 목록 표시는 생성 시각 순으로 해 삭제된 슬롯을 다시 써도 새 항목이 마지막에 온다.
- 저장소 테스트에서 목록 정렬, 사용자 범위, 5개 제한, 존재하지 않거나 타인 소유인 ID, 수정 시각을 검증한다.

### Task 3: 저장 프롬프트 API

- `GET`·`POST /api/saved-prompts`, `PATCH`·`DELETE /api/saved-prompts/[id]`를 제공한다.
- 비로그인 요청은 401, 입력 오류는 400, 저장 한도는 409, 처리 실패는 사용자에게 이해 가능한 오류로 반환한다.
- 라우트 테스트에서 인증, 사용자 격리, CRUD 성공, 잘못된 요청, 6번째 생성 거부를 검증한다.

### Task 4: 사용자별 클라이언트 데이터 흐름

- `src/features/saved-prompt/`에 목록 query와 생성·수정·삭제 mutation 훅을 각각 둔다.
- Query key에 서버가 페이지에 전달한 현재 사용자 ID를 포함하고, 각 mutation 성공 뒤 해당 사용자의 목록을 무효화한다.
- 훅 테스트에서 API 요청과 캐시 갱신을 검증한다.

### Task 5: 생성 화면 프롬프트 선택

- 저장 프롬프트 선택과 새 의견 입력을 전환하는 UI를 추가한다. 저장 프롬프트 선택 목록은 제목을 표시한다.
- 생성 요청에는 선택된 저장 프롬프트의 `content` 또는 새 의견 중 하나만 전달한다. 아무것도 고르지 않으면 기존 기본 프롬프트 동작을 유지한다.
- 화면 테스트에서 두 입력 경로의 배타성과 생성 요청 내용을 검증한다.

### Task 6: 프롬프트 관리 다이얼로그

- 생성 화면에서 여는 다이얼로그에 목록·생성·수정·삭제 동작을 제공한다.
- 첫 사용 빈 상태, 로딩, 오류 및 재시도, 5개 저장 한도, 입력 오류, 저장 성공 후 목록 동기화를 구현한다.
- 접근성 테스트에서 다이얼로그 제목, 키보드 닫기, 포커스 복귀, 필드 라벨과 오류 연결을 확인한다.

### Task 7: 통합 검토 및 검증

- 전체 테스트를 실행하고 UX 리뷰 결과로 필요한 수정을 한다.
- PR 전 `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run format:check`를 실행한다.
- 변경 사항을 검토하고 PR을 생성한다. PR은 생성하되 병합하지 않는다.

## 입력 길이 결정

제목 최대 길이는 아직 정해지지 않았다. 구현 전 손 대표님 확인이 필요하다. 제안은 제목 30자다. 선택 목록에서 읽기 쉽도록 제한한다. 내용은 손 대표님 결정에 따라 최대 300자로 한다.

## 검토할 실패 사례

- 로그인하지 않은 요청은 401이고 다른 사용자의 프롬프트 ID는 조회·수정·삭제할 수 없다.
- 저장 5개일 때 6번째 생성은 409와 사용자 안내를 반환한다.
- 잘못된 ID, 비어 있거나 제한보다 긴 제목·내용, 잘못된 JSON을 거부한다. 내용은 300자를 초과할 수 없다.
- 저장 프롬프트를 고르면 그 내용이 생성 요청에 반영되고, 새 의견 또는 미선택은 서로 올바른 프롬프트 동작을 따른다.
- 목록 조회와 저장·수정·삭제 중 UI의 로딩·빈·오류 상태가 구분된다.
