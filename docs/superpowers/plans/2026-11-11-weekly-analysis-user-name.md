# 주간 분석 화면과 카카오 닉네임 표시 구현 계획

## 승인된 기준

- 주간 통계는 MongoDB에 저장된 전체 공개 회차를 사용하고 마지막 기준 회차를 표시합니다.
- 저수/고수는 1–22 / 23–45, 번호 구간은 1–10 / 11–20 / 21–30 / 31–40 / 41–45입니다.
- 연속수는 인접 번호 쌍 수와 회차별 최장 연속 길이로 요약합니다.
- 로그인 상단에는 필수 동의된 카카오 프로필 닉네임을 표시하고 MongoDB에 저장합니다. 선택 동의 이메일은 요청·저장하지 않습니다.
- 아직 당첨 번호 자료를 수집하지 않았으므로 데이터가 없는 상태를 화면에서 안내합니다. 제공처 선택과 수집 작업은 별도 이슈 #9입니다.

## 작업 순서

1. **카카오 닉네임 저장과 조회**
   - 인가 요청에 `profile_nickname`만 지정합니다.
   - 사용자 정보 응답의 카카오 ID와 닉네임을 검증합니다.
   - `users` 문서에 닉네임을 저장·갱신하고, 세션 사용자 조회에서 닉네임을 반환합니다.
   - OAuth 요청, 응답 검증, 사용자 저장, 세션 조회 테스트를 먼저 추가합니다.

2. **헤더의 사용자 표시**
   - 현재 `카카오 로그인됨` 문구를 닉네임으로 바꿉니다.
   - 홈페이지와 분석 화면에서 같은 FSD 헤더를 사용합니다.
   - 기존 세션처럼 저장 닉네임이 없는 경우의 fallback과 로그인 후 갱신을 테스트합니다.

3. **통계 계산**
   - `lottery_draws` 자료를 입력받는 순수 계산 함수를 둡니다.
   - 번호별 출현 횟수·미출현 회차, 홀짝·저고 분포, 5개 구간 분포, 연속수 쌍·최장 길이를 계산합니다.
   - 정렬·중복·범위와 빈 입력을 테스트하고 입력 순서가 달라도 결과가 같도록 합니다.

4. **주간 분석 페이지**
   - 인증 사용자만 접근하는 `/analysis` 페이지를 추가합니다.
   - 서버에서 `lottery_draws`를 조회하고 통계를 계산합니다.
   - 데이터 없음, 로드 실패, 분석 결과 상태를 각각 표시하고 기준 회차 및 참고 안내를 보여줍니다.
   - 홈페이지에서 분석 화면으로 이동할 수 있게 하고, 두 화면 상단에 로그인 사용자 닉네임을 표시합니다.

5. **문서·이슈 동기화와 검증**
   - `spec.md`, `architecture.md`, 이슈 #5 및 닉네임 이슈를 구현과 일치시킵니다.
   - 프론트엔드·백엔드 흐름이 완성되면 `ux-review`로 검토합니다.
   - 그 뒤 포맷, 린트, 타입 검사, 테스트, 빌드를 실행하고 PR을 엽니다. 병합 및 GitHub CI 확인은 하지 않습니다.
