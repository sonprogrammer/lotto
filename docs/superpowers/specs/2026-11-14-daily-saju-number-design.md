# 오늘의 사주 숫자 추천 설계 초안

상태: 설계 승인됨. `spec.md`와 `architecture.md`에 반영했으며 구현 중.
관련 이슈: [#42 오늘의 사주 기반 숫자 추천](https://github.com/sonprogrammer/lotto/issues/42)

## 목적

로그인 사용자가 메인 화면에서 한국시간 기준 오늘의 사주 숫자 하나를 확인하게 합니다. 기존 통계 기반 6개 조합 추천과 구분되는 가벼운 일일 콘텐츠입니다.

## 합의된 요구사항

- 카카오 로그인 사용자만 사용합니다. 게스트에게는 기존 무작위 6개 번호 미리보기만 제공합니다.
- 사용자 프로필에는 이름을 별도 입력하고, `YYYY-MM-DD` 생년월일과 양력·음력 구분을 저장합니다. 이름은 사주 계산 및 AI 입력에 사용하지 않습니다.
- 출생 시각은 선택 입력입니다. 입력하지 않으면 계산 시 정오를 기준으로 연주·월주·일주를 구하고 시주는 추천 근거에서 제외합니다.
- 한국시간(Asia/Seoul) 날짜를 오늘의 기준으로 사용합니다.
- 로그인 사용자의 메인 화면에서 오늘 결과를 표시합니다. 오늘 결과가 없으면 서버가 만세력 계산 후 Groq에 숫자 하나와 한국어 설명을 요청합니다.
- 같은 사용자·같은 한국 날짜의 결과가 DB에 있으면 기존 결과를 그대로 보여주고 AI를 다시 호출하지 않습니다.
- 추천 숫자는 1~45의 정수 하나이며, 결과와 설명을 MongoDB에 저장합니다.
- 당첨 확률을 높이거나 당첨을 예측한다고 표현하지 않습니다. 사주 숫자는 재미용 참고 정보입니다.

## 검토한 구현 방식

1. **AI가 숫자를 직접 고름 (선택안)**: 서버에서 계산한 사주 요약을 Groq에 보내 숫자와 이유를 받습니다. 사용자가 원한 AI 추천에 맞습니다. 응답 검증과 중복 생성 방지가 필요합니다.
2. **서버 규칙이 숫자를 고르고 AI는 설명만 작성**: 재현성과 출력 통제가 쉽지만 숫자 추천 자체는 AI가 하지 않습니다.
3. **사주 라이브러리만으로 숫자를 정함**: AI 비용은 없지만 숫자로 변환하는 별도 임의 규칙이 필요하고, AI 추천이라는 요구에 맞지 않습니다.

손 대표님은 1번을 선택했습니다. 서버는 기존 Groq 연동을 재사용하고, 엄격한 JSON 스키마로 응답을 받아 숫자 범위와 한국어 설명을 검증합니다.

## 제안하는 처리 흐름

1. 홈 화면은 세션을 확인합니다. 게스트는 기존 랜덤 미리보기를 유지합니다.
2. 로그인 사용자는 사주 프로필이 있으면 오늘 결과를 요청합니다. 프로필이 없으면 오늘 숫자를 만들지 않고 프로필 입력 흐름을 안내합니다.
3. 개인 데이터이므로 서버는 인증된 세션의 사용자 ID로만 프로필과 결과를 조회합니다. API 응답은 `private, no-store`를 사용하고 TanStack Query 캐시 키는 사용자 ID와 KST 날짜로 분리합니다.
4. 서버는 먼저 `{ userId, dateKey }` 결과를 조회합니다. 결과가 있으면 이를 반환합니다.
5. 결과가 없으면 프로필과 현재 KST 날짜를 `manseryeok`으로 계산합니다. 음력은 윤달 여부도 함께 받습니다. 출생 시각이 없는 경우 계산 호출에 정오를 사용하되, 반환된 시주는 AI 입력에서 제외합니다.
6. Groq에는 출생 이름, 원본 생년월일, 계정 ID를 보내지 않습니다. 출생 차트의 필요한 기둥과 오늘의 일주만 전송합니다.
7. AI는 `{ number, explanation }` JSON을 반환합니다. 서버는 `number`가 1~45 정수인지, 설명이 한국어이며 짧은지 검사합니다.
8. MongoDB에 사용자·KST 날짜별 결과를 저장합니다. 복합 고유 인덱스와 30초 만료 생성 선점으로 동시 접속의 중복 AI 호출과 결과 중복을 막습니다. 서버가 중간에 종료돼 선점이 남아도 만료 후 다시 시도할 수 있습니다.
9. 일시 실패는 오류와 재시도 방법을 보여줍니다. 실패한 시도는 성공 결과를 만들지 않았으므로 재시도에서 AI를 다시 호출할 수 있습니다.

## 데이터 제안

- 사용자 문서에 별도 `sajuProfile` 하위 문서를 둡니다: 선택 표시 이름, `YYYY-MM-DD` 생년월일, 양력·음력, 음력 윤달 여부, 선택 `HH:mm` 출생 시각, 생성·수정 시각.
- 별도 `dailySajuRecommendations` 컬렉션에 사용자 ID, `dateKey` (`YYYY-MM-DD`, KST), 숫자, 한국어 설명, 상태, 생성 시각을 저장합니다. `generating` 상태에는 30초 만료 시각을 함께 저장합니다.
- `{ userId, dateKey }`에 유일 인덱스를 둡니다. 사용자 프로필과 결과는 공용 Next.js 캐시에 넣지 않습니다.
- 출생 프로필 삭제 시 해당 사용자의 과거 일일 추천 기록도 함께 삭제합니다.

## UI 상태

- 사주 프로필 미등록: 이름과 출생정보 등록을 안내합니다.
- 오늘 결과 생성 중: 메인 카드의 콘텐츠에 맞는 스켈레톤과 진행 문구를 보여줍니다.
- 성공: 날짜, 숫자 공 하나, 짧은 설명, 재미용 참고 안내를 보여줍니다.
- 실패: 오류 내용을 과장하지 않고 재시도 동작을 제공합니다.
- `prefers-reduced-motion`을 따르며 숫자 공개 애니메이션은 선택적으로 적용합니다.

## 기존 문서에 반영할 내용

- `spec.md`: 일일 사주 숫자를 첫 버전 기능으로 옮기고, 프로필 입력·메인 노출·한국 날짜별 저장·AI 추천 요구사항과 개인정보 안내를 반영했습니다.
- `architecture.md`: `manseryeok` 의존성(MIT), 서버 측 만세력 계산, Groq 입력 범위와 검증, 개인 데이터 캐시, MongoDB 인덱스 및 동시 생성 방지 설계를 반영했습니다.
- 기존 사용자 문서의 이름은 카카오 닉네임과 별개인 사주 프로필 표시 이름입니다. 카카오 닉네임 필드와 혼합하지 않습니다.

## 승인된 세부 결정

- 사주 프로필 표시 이름은 선택 입력이며 카카오 닉네임과 분리합니다.
- 음력 윤달 선택은 음력 날짜를 선택한 경우에만 표시합니다.
- 사주 프로필 최초 입력은 홈에서 바로 할 수 있게 합니다.
- 로그인 홈에는 오늘의 사주 숫자를 표시하고, 비로그인 홈에는 기존 랜덤 6개 미리보기를 유지합니다.
- 사주 프로필을 삭제하면 해당 사용자의 과거 일일 사주 추천도 함께 삭제합니다.
- 구현은 승인된 요구사항과 `spec.md`·`architecture.md`에 따라 진행합니다.
