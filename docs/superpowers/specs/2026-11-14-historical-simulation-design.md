# 이슈 #12 과거 회차 시뮬레이션 설계 초안

상태: 손 대표님 승인

## 목적

통계 기반 번호 생성 규칙을 과거 회차에 적용하고, 생성 조건과 실제 당첨 결과를 비교해 규칙의 과거 성적을 확인합니다. 이는 과거 자료에 대한 재현 실험이며 미래 당첨 확률을 높이거나 보장하지 않습니다.

## 범위 제안

- Groq 등 생성형 AI는 호출하지 않습니다. 기존의 통계 기반 생성 규칙만 재현합니다.
- 평가 대상은 최신 당첨 회차를 포함하지 않는 **최근 완료 30회차**로 합니다. 최신 결과가 아직 동기화되지 않았다면 동기화된 최신 회차를 기준으로 삼습니다.
- 대상 회차마다 그 회차 추첨 전에 공개된 직전 30회차만 분석에 사용합니다. 직전 30회차가 없는 초기 구간은 대상에서 제외합니다.
- 각 대상 회차에 대해 기본 5개 조합을 생성합니다. 사용자가 1~10개 사이에서 개수를 바꿀 수 있게 합니다.
- 같은 설정으로 다시 실행하면 같은 번호 조합과 성적이 나오도록 대상 회차, 생성 규칙 버전, 설정을 재현 조건에 기록합니다.
- 회차별 결과와 요약에서 1~5등 일치 건수, 총 구매 비용, 총 당첨금, 순손익을 보여줍니다. 티켓 1장 비용은 회차 당시가 아니라 현재의 1,000원 기준으로 환산합니다.
- 실제 회차별 1인당 당첨금 자료를 사용해 당첨금을 계산합니다. 자료가 없는 등위는 임의로 채우지 않고, 확인 가능한 데이터만 합산하며 누락 사실을 표시합니다.
- 실행 내역과 결과는 로그인한 사용자의 계정에 저장하고, 본인만 다시 조회할 수 있게 합니다.

## 회차별 계산

1. 각 대상 회차의 직전 30회 당첨 자료를 고정된 시점의 입력으로 만듭니다.
2. 번호별 출현 통계와 홀짝·고저·구간·연속수 등 기존 생성 규칙을 적용합니다.
3. 기록된 시드와 규칙 버전을 사용해 설정한 수의 조합을 생성합니다.
4. 생성 조합을 대상 회차의 당첨 번호와 보너스 번호에 대조해 등수를 판정합니다.
5. 대상 회차의 등위별 1인당 당첨금과 조합 수를 사용해 회차별 비용·당첨금·순손익을 계산합니다.

## 데이터 보관과 접근

- 실행별 조건·요약과 회차별 결과를 사용자 계정에 귀속해 저장합니다.
- 재실행은 새 실행 기록으로 저장하며 이전 기록을 덮어쓰지 않습니다.
- API는 인증된 사용자의 실행만 조회·삭제할 수 있도록 사용자 ID를 항상 범위 조건에 포함합니다.
- 과거 당첨 자료는 공통 데이터로 조회하고, 실행 결과는 개인 데이터로 분리합니다.

## 주의할 점

- 결과는 선택한 기간과 과거 통계 규칙에 대한 후행 시뮬레이션입니다. 미래 결과를 예측하거나 당첨 확률을 개선한다는 근거가 아닙니다.
- 실제 과거 당첨금은 당시 판매량·당첨자 수에 따라 달라졌습니다. 이 비교는 확인된 회차별 1인당 당첨금을 적용한 가상 구매 합계입니다.
- 같은 조합이 한 회차의 5개 생성 결과 안에서 중복되지 않도록 합니다. 조건을 만족하는 조합이 부족하면 실패 이유를 알리고 조건을 임의 완화하지 않습니다.

## 승인 후 구현 항목

- 회차 시점 데이터 절단과 누출 방지 검증
- 통계 기반 생성 규칙의 결정적 재현
- 사용자별 시뮬레이션 실행·결과 저장과 조회
- 기간·조합 수 설정, 전체 요약과 회차별 결과 화면
- 같은 설정 재현 및 사용자 데이터 격리 검증, UI가 있는 흐름의 UX 검토

## 승인 확인이 필요한 제안

위 내용대로 **최근 완료 30회차**, 회차당 기본 5조합(선택 1~10), 직전 30회차 통계, 실제 등위별 당첨금, 사용자별 실행 저장, 회당 1,000원 비용 가정으로 진행합니다. 달리 원하시는 기준이 있으면 구현 전에 수정하겠습니다.
