# 비로그인 홈 랜딩 경험 설계 초안

상태: 승인됨. `spec.md`와 `architecture.md`에 요구사항을 반영했으며 구현 계획을 작성 중입니다.

## 목적

비로그인 방문자가 랜덤 번호를 바로 체험하게 하고, 로그인하면 매일 사주 기반 행운 숫자를 받을 수 있다는 가치를 첫 화면에서 이해하게 합니다.

## 검토한 방향과 선택

1. **현재 중앙 화면을 꾸미고 안내를 아래에 추가**: 기존 흐름을 유지하고 구현 범위가 작지만, 첫 화면에서 체험과 서비스 가치를 함께 전달하기 어렵습니다.
2. **좌우 히어로 구성 (선택)**: 데스크톱 왼쪽에 서비스 소개·오늘의 사주 숫자 로그인 혜택을, 오른쪽에 랜덤 번호 체험을 배치합니다. 모바일에서는 랜덤 체험을 먼저 보여주고 소개를 이어 배치합니다. 첫 화면에서 체험과 로그인 이유를 모두 보여줍니다.
3. **여러 구역으로 된 긴 소개 페이지**: 기능 설명을 충분히 넣을 수 있지만, 번호를 바로 뽑으려는 방문자에게 첫 화면이 길어집니다.

손 대표님은 2번 좌우 히어로 구성을 선택했습니다.

## 요구사항

- 비로그인 화면의 주요 동작은 기존처럼 통계나 AI를 쓰지 않는 무작위 6개 번호 생성입니다.
- 번호 공이 섞이고 첫 번째부터 여섯 번째까지 차례로 공개되는 기존 효과를 유지합니다. 뒤집기 효과는 사용하지 않습니다.
- 비로그인 사용자는 브라우저당 최대 세 번 번호를 생성할 수 있습니다. 네 번째 시도는 번호를 생성하지 않고 Sonner 알림으로 카카오 로그인 후 계속 이용할 수 있음을 안내합니다.
- 체험 횟수는 `localStorage`에 저장해 새로고침과 같은 브라우저의 재방문 후에도 유지합니다. 생성 버튼을 누를 때 횟수를 기록해 생성 도중 페이지를 닫아도 횟수가 되돌아가지 않게 합니다.
- 현재 방문이 몇 번째 체험인지 알아볼 수 있게 `1/3회` 형태로 표시합니다. 세 번을 사용한 뒤에도 버튼은 로그인 안내 알림을 띄우기 위해 사용할 수 있습니다.
- 로그인 혜택 영역에는 “로그인하면 매일 사주 기반 행운 숫자를 확인할 수 있다”는 문구와 카카오 로그인 경로를 제공합니다. 실제 사주 숫자나 사용자의 사주 정보는 게스트 화면에 만들거나 표시하지 않습니다.
- 첫 화면의 장식 애니메이션은 짧고 절제하며 `prefers-reduced-motion`을 따릅니다. 번호 공 애니메이션 동작은 기존 규칙을 유지합니다.

## 제한과 비목표

- 로그인 전에는 서버가 방문자 신원을 알 수 없으므로 제한은 사람 단위가 아니라 브라우저 저장소 단위입니다. 다른 브라우저·기기 또는 사이트 데이터 초기화로 체험 횟수가 초기화될 수 있습니다. 계정·IP 추적이나 서버 저장은 개인정보·운영 범위를 키우므로 이번 작업에 넣지 않습니다.
- 랜덤 번호를 분석 추천 또는 당첨 예측으로 표현하지 않습니다.
- 로그인 이후의 홈 화면과 일일 사주 생성·저장 흐름은 바꾸지 않습니다.
- 새 UI 라이브러리나 외부 사주 API를 추가하지 않습니다. 기존 Sonner 알림과 로그인 버튼을 재사용합니다.

## 남은 구현 선택

- 첫 화면 배치, 여백, 배경과 동작은 기존 Tailwind/CSS 기준에 맞춰 구현자가 조정합니다.
- 브라우저 저장소를 읽기 전에는 버튼을 잠시 비활성화해 저장된 제한 횟수를 불러오기 전에 추가 생성되는 경우를 막습니다.
- 저장 데이터가 없거나 손상된 경우 0회로 시작합니다. 저장소 접근 자체가 불가능한 브라우저에서의 횟수 보장은 할 수 없으며, 이 경우 체험은 동작하게 두고 브라우저 제한임을 안내합니다.

## 승인 후 문서 반영

승인되면 `spec.md`의 로그인 전 미리보기 요구사항에 3회 제한, 횟수 보존, 로그인 안내와 사주 가치 설명을 반영합니다. `architecture.md`에는 횟수가 브라우저별 공통 데이터가 아닌 로컬 UI 상태이며 서버 저장·캐시를 사용하지 않는다는 점을 필요한 만큼만 추가합니다.
