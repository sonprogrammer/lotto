# 회차별 당첨 번호 수동 확인 설계

> 상태: 손 대표님이 수동 확인 버튼과 공통 동기화 경로 재사용을 승인함

## 의도

정기 Vercel Cron이 늦거나 실패했을 때 로그인 사용자가 회차별 당첨 내역 화면에서 최신 공개 결과를 직접 확인하고 싶을 수 있습니다. 이 기능은 결과를 보장된 시각에 제공하지 않으며, 동행복권 결과 자료에 새 내용이 있을 때만 기존 동기화 규칙으로 저장합니다.

## 목표와 제외 범위

- 회차별 당첨 내역 화면에 `당첨 번호 확인` 버튼을 제공합니다.
- 버튼은 인증된 서버 API를 호출하고, 정기 Cron과 분석 요청이 이미 사용하는 `syncAndReconcileSavedCombinationDrawResults` 경로를 재사용합니다.
- 처리 중에는 버튼을 비활성화하고, 최신 자료 반영·변경 없음·실패를 화면에 알립니다.
- 결과가 바뀌면 공통 회차 자료와 분석 캐시를 다시 불러옵니다.
- 새 예약 서비스, 새 데이터 저장 방식, 비로그인 동기화, 외부 소스 직접 호출을 추가하지 않습니다.

## 접근 방식

1. **전용 인증 API + 기존 동기화 서비스 재사용 (선택)**: UI 동작이 분석 요청과 분리되고, 서버가 기존 검증·저장·당첨 알림 처리를 유지합니다.
2. **분석 API 재사용**: 이미 분석 API가 동기화하지만, 사용자가 확인만 원해도 분석 요청을 수행하고 관심사 두 개를 결합합니다.
3. **브라우저에서 결과 제공처 직접 조회**: 비밀 설정과 데이터 저장 책임이 클라이언트로 이동하고 기존 검증·캐시 무효화 흐름을 우회합니다.

손 대표님은 1번 접근 방식과 처리 상태 안내를 승인했습니다.

## 동작

- 로그인 확인 후 전용 `POST /api/lottery-draws/sync` 경로에서 기존 동기화 함수를 한 번 시도합니다.
- 결과가 달라졌을 때만 당첨 내역 및 주간 분석의 Next.js 공유 캐시를 무효화합니다. 동기화 상태는 매번 갱신합니다.
- 클라이언트는 TanStack Query 캐시를 갱신하고, 중복 클릭을 막습니다.
- 새 자료가 반영되면 최신 회차를 알립니다. 바뀐 내용이 없으면 현재 반영된 최신 회차를 알려줍니다. 오류에는 다시 시도할 방법을 보여줍니다.
- 실제 제공처 공개 시각과 Cron 실행 시각이 다를 수 있음을 화면의 기존 안내와 함께 유지합니다.
