# 작업 완료 토스트 설계

## 목적

번호·프롬프트를 저장하거나 수정·삭제한 뒤 화면이 바뀌어도 작업이 완료됐음을 짧고 일관되게 알린다.

## 범위

- 일반 화면용 Sonner 토스트를 앱 루트에 설정한다.
- 네이티브 프롬프트 설정 모달 내부에는 별도 Toaster를 두어 모달의 top layer와 접근성 경계 안에서 알림을 표시한다.
- 수동 번호 저장, 저장 번호 수정·삭제, 저장 프롬프트 생성·수정·삭제 성공에 토스트를 표시한다.
- 생성 결과의 “저장 완료”처럼 이미 화면에 성공 상태가 남는 경우에는 중복 토스트를 띄우지 않는다.
- 재시도나 입력 수정이 필요한 오류는 기존 화면 내 오류 안내를 유지한다.
- 기존 알림함과 푸시 알림 동작은 바꾸지 않는다.

## 접근 방식

- **Sonner 토스트 (선택):** 앱에 한 번 설치하고 필요한 성공 지점에서 호출한다. 가벼운 통합으로 기존 화면을 크게 바꾸지 않는다.
- 공통 자체 토스트 UI: 스타일·동작을 직접 관리해야 하므로 이번 작은 범위에는 비용이 크다.
- 모든 성공·오류를 토스트로 교체: 오류 내용을 사용자가 조치할 때까지 유지하기 어려워 현재 인라인 오류를 남기는 편이 낫다.

## 남은 구현 판단

토스트는 한국어 문구, 상단 중앙, 약 3.5초 노출을 기본으로 한다. 기존 성공 표시가 더 명확한 화면은 그대로 둔다.
