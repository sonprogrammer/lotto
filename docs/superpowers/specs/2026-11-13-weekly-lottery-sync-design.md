# 이슈 9: 당첨 번호 주간 자동 반영 설계 초안

> 상태: 손 대표님 승인

## 목적

당첨 번호와 등수별 당첨금을 주 1회 자동으로 동기화해 분석과 저장 조합 확인에 반영하고, 사용자가 마지막 반영 시각과 다음 예상 갱신 시각을 확인할 수 있게 합니다.

## 범위

- AI 검색 API를 사실 데이터의 원천으로 사용하지 않습니다. Vercel Cron으로 매주 토요일 21시대(한국 시간)에 현재 코드가 사용하는 동행복권 결과 조회 JSON 주소를 운영 배포 서버에서 호출합니다. 이는 동행복권 공식 웹사이트의 공개 결과 자료를 저빈도로 조회하는 방식이며, 별도 공식 Open API 또는 명시적 재사용 허가를 받은 API라고 표현하지 않습니다.
- Vercel Hobby는 시간대 안에서 실행 시각이 달라질 수 있고 실패 자동 재시도가 없으므로, 호출 안에서 제한된 재시도를 하고 실패 상태를 저장합니다.
- `CRON_SECRET`으로 호출을 인증합니다. 실패 후에는 기존 분석/생성 등의 동기화 요청으로 복구할 수 있게 유지합니다.
- 기존 `lottery_draws` 자료는 회차 고유 인덱스와 upsert 방식으로 저장하므로 같은 회차 재실행 시 중복 자료가 생기지 않습니다.
- 동기화 실행 상태는 MongoDB의 단일 상태 문서에 최근 시도 시각, 마지막 성공 시각, 상태, 최신 회차, 오류 요약을 보관합니다. 별도 영구 작업 이력은 이번 범위에 넣지 않습니다.
- 회차별 당첨 내역 화면에 마지막 성공 시각과 다음 예상 갱신 시각을 표시합니다. 다음 시각은 토요일 21시대의 예정 안내이며 실제 데이터 공개·작업 실행 시각과 다를 수 있음을 함께 알립니다.
- 주간 작업은 최신 회차를 우선 확인하고, 새 회차나 저장 자료 이상이 확인될 때만 전체 회차 자료를 다시 가져옵니다. 기존 합의대로 과거 회차의 늦은 정정은 전체 회차 동기화가 다시 수행될 때 반영하며, 매주 전체 이력을 강제로 재조회하지 않습니다.
- 요청은 주 1회로 제한하고 인증 우회나 과도한 재요청을 하지 않습니다. 다른 사이트도 공개 자료를 수집해 제공한다는 사례는 참고하되, 그 사례 자체를 이용 허가의 증거로 보지는 않습니다.
- 저장 조합의 회차별 당첨 비교 및 사용자 알림은 이슈 #10 범위로 둡니다.

## 제외 범위

- 공식 API 접근 권한 또는 명시적 데이터 재사용 허가 협의
- 즉시 과거 정정 감지, 관리자용 실행 이력 대시보드
- 저장 조합 당첨 비교와 푸시 알림

## 구현 접근 대안

1. **Vercel Cron + 동행복권 공개 결과 조회 주소**: 현재 호스팅에 붙어 있고 별도 예약 서비스가 필요 없습니다. Hobby에서는 주 1회 실행 비용이 별도로 들지 않지만 실행 시각이 시간대 단위이고 자동 재시도가 없습니다. 손 대표님이 선택한 방식입니다. 주소가 공식 Open API라는 뜻은 아닙니다.
2. **GitHub Actions 예약 실행**: Vercel Cron 한도와 분리할 수 있지만 저장소의 기본 브랜치에서만 예약이 동작하고, 저장소 비밀값과 외부 서비스 호출 설정을 추가로 관리해야 합니다.
3. **외부 작업 서비스**: 스케줄과 재시도 설정이 유연하지만 MVP에 외부 서비스와 운영 설정이 추가됩니다.

## 실패·중복·정정 처리

- Cron 중복 호출은 회차 고유 인덱스와 upsert로 데이터 중복을 막습니다.
- 한 번의 Cron 요청 안에서 일시 오류를 제한 횟수 재시도합니다. 재시도가 끝나도 실패하면 실패 시각과 안전한 오류 요약을 남기고 다음 사용자 요청에서 복구를 시도합니다.
- 잘못된 형식, 불완전한 회차 범위, 최신 회차 불일치는 현재 검증 절차대로 거부하고 성공으로 기록하지 않습니다.
- 새 회차 등 전체 자료 동기화가 필요한 경우 과거 회차 정정도 함께 반영합니다. 전체 자료를 매주 강제로 확인하지 않으며, 기존에 합의한 정정 지연을 허용합니다.
- 비밀값, 전체 외부 응답, 개인 사용자 자료를 로그에 기록하지 않습니다.

## 승인 후 구현할 항목

- Vercel Cron 설정과 인증된 동기화 API 경로
- MongoDB 동기화 상태 문서 및 실패 처리
- 상태 조회 API와 회차별 당첨 내역 화면의 마지막/다음 갱신 정보
- 출처와 비공식 공개 응답 사용 제한을 프로젝트 문서에 기록
- 경계 조건 테스트, UX 검토, 프로젝트의 PR 전 로컬 검증

## 사용자 설정

- Vercel 프로젝트의 Production 환경 변수에 `CRON_SECRET`을 설정해야 합니다. 값은 손 대표님이 생성해 Vercel 대시보드에 직접 입력하며 저장소나 채팅에 공유하지 않습니다.
- Cron은 Production 배포에서만 실행됩니다. 별도 로컬 비밀값은 손 대표님이 로컬에서 실제 실행을 원할 때 직접 설정하면 됩니다.

## 참고

- Vercel Cron은 프로젝트의 `vercel.json` 설정을 사용하며 UTC 기준으로 스케줄을 지정합니다. `0 12 * * 6`은 토요일 12:00 UTC, 즉 한국 시간 토요일 21:00입니다.
- Hobby 실행 시각은 해당 시간대 안에서 달라질 수 있고, Vercel은 실패한 호출을 자동 재시도하지 않으므로 애플리케이션에서 이를 처리합니다.
- 현재 동행복권 주소는 코드에서 사용 중인 공식 웹사이트의 공개 결과 응답입니다. 이번 설계는 이를 주 1회 조회하는 것으로 정했으며, 별도 공식 API 명세나 명시적 재사용 허가가 확인됐다고 주장하지 않습니다. 공개된 다른 서비스의 사용 사례만으로 법적 허가 여부를 단정하지 않습니다.
