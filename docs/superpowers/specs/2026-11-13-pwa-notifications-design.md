# Issue #11: 사이트 알림함과 선택형 PWA 푸시 설계 초안

## 목적

로그인 사용자가 저장한 조합에서 1~5등 결과가 확인되면 사이트 알림함에 기록하고, 사용자가 구독한 기기에는 Web Push를 보냅니다. 푸시를 허용하지 않아도 알림함과 읽음 상태는 사용할 수 있습니다.

## 현재 상태와 제약

- Issue #10의 저장 조합별 `drawResults` 계산과 회차 동기화 유스케이스가 `main`에 병합됐습니다.
- 사이트에 웹 앱 매니페스트와 서비스 워커는 아직 없습니다.
- 사이트 데이터는 MongoDB에 저장하고 서버 코드에서만 사용자 소유 데이터를 다룹니다.
- 실제 브라우저 푸시 권한은 사용자의 명시적 동작으로만 요청합니다. 로그인 직후 자체 안내를 보여도 브라우저 권한 팝업을 자동으로 띄우지 않습니다.
- iOS에서 PWA 푸시를 받으려면 iOS 16.4 이상에서 사이트를 홈 화면에 설치해야 합니다.
- 사용자가 중복 푸시보다 중복 방지를 우선하기로 했습니다. 알림함 기록은 항상 보존하고, 전송 접수 여부가 불분명한 요청은 재전송하지 않습니다. 이 경우 푸시 누락 가능성은 남습니다.

## 목표

- 로그인 사용자가 본인 알림 목록과 읽지 않은 개수를 확인하고 항목을 읽음 처리합니다.
- 1~5등 결과를 조합·회차마다 알림함에 한 번만 기록합니다.
- 푸시 구독은 기기별로 저장하고 해당 사용자의 세션으로 등록·해지합니다.
- 푸시를 허용한 활성 기기에만 알림을 전송하고, 영구 만료된 구독은 삭제합니다.
- 최초 로그인 후 브라우저별로 안내를 한 번 보여주고, 알림함에서 나중에도 구독 상태를 관리할 수 있게 합니다.
- 동기화·분석·생성·저장 요청 재실행으로 알림함 항목이나 푸시 전송 시도가 중복되지 않게 합니다.

## 범위에서 제외

- 카카오톡 메시지, 이메일, SMS 알림
- 알림 등급별 설정, 알림 빈도 설정
- 읽은 알림의 장기 보관·자동 삭제 정책
- 전송 접수 여부가 불확실한 푸시의 자동 재시도
- 과거 모든 당첨 이력에 대한 초기 알림 일괄 발송

## 접근 방식

### A. MongoDB 알림함 + 표준 Web Push (선택)

알림함, 기기별 구독, 기기별 전송 이력을 MongoDB에 기록합니다. `web-push`와 VAPID로 브라우저 서비스 워커에 전송합니다. 무료 운영과 현재 서버 구조를 유지하면서 전체 요구를 충족합니다. 서비스 워커·매니페스트·서버 환경 변수가 필요하며, 푸시 전송은 at-most-once 시도로 제한합니다.

### B. 알림함 먼저, 푸시는 후속 구현

외부 전송을 미루므로 초기 구현은 더 작지만 Issue #11의 선택형 PWA 푸시 범위를 완성하지 못하고 별도 재작업이 필요합니다.

### C. 관리형 푸시 서비스

서비스 워커와 일부 브라우저 차이를 줄일 수 있지만 외부 공급자에 사용자·기기 구독 정보가 추가로 전달되고 프로젝트의 무료·자체 운영 방향에서 벗어날 수 있습니다.

**선택:** A. 사이트 알림함은 결과의 영속 기록으로 두고, Web Push는 구독한 기기에 전달하는 보조 경로로 둡니다.

## 승인된 제품 동작

- 저장 조합에서 1~5등을 얻으면 사이트 알림함에 기록합니다.
- 기기에서 푸시를 허용하고 구독이 활성화된 경우 해당 기기로 알립니다.
- 최초 로그인 후 안내는 브라우저별 한 번 표시합니다. `알림 켜기`와 `나중에`를 제공합니다. `나중에` 선택 여부는 해당 브라우저에 기억하고, 알림함 화면에서 다시 켤 수 있습니다.
- 브라우저 권한 요청은 `알림 켜기`를 누른 동작에서 시작합니다. 브라우저 권한이 차단된 경우 재요청을 강제하지 않고 설정 안내를 보여줍니다.
- 알림 목록은 최신순으로 보여주며 각 항목의 읽음 여부를 변경하고 읽지 않은 개수를 표시합니다.
- 알림을 누르면 저장한 조합 화면으로 이동합니다. 푸시 잠금 화면 문구에는 번호, 닉네임, 당첨금 등 민감 정보를 넣지 않습니다.
- 최신 회차 결과 정정은 알림함의 동일 회차 항목을 갱신합니다. 이미 처리한 푸시를 다시 보내지 않습니다. 당첨이 취소되면 알림함 항목을 정정 상태로 표시합니다.
- 다른 기기에서 로그인해도 새 기기는 별도 구독할 수 있습니다. 같은 브라우저 구독은 현재 로그인 계정에 귀속합니다.
- 로그아웃할 때 현재 브라우저의 푸시 구독만 해지하고, 다른 기기의 구독은 유지합니다. 서버는 인증된 `userId`와 현재 기기 endpoint가 모두 일치하는 구독만 삭제한 뒤 세션을 종료합니다. 구독 삭제가 실패하면 로그아웃도 실패로 반환해 활성 구독이 계정에서 분리되는 것을 막고, 사용자는 다시 시도할 수 있습니다.

## 중복과 전송 실패 정책

- 알림함 중복 키는 `{ userId, savedCombinationId, roundNumber }`입니다. MongoDB 고유 인덱스와 upsert로 동기화 재시도를 멱등하게 처리합니다.
- 기기 구독은 Web Push endpoint 기준으로 고유하게 관리하고, 삭제·조회에는 인증 세션의 `userId`를 함께 적용합니다.
- 알림별 기기 전송 이력은 `{ notificationId, subscriptionId }` 고유 키로 저장합니다.
- 전송 전에 해당 기기의 발송 시도를 원자적으로 선점하고, 선점된 건은 재시도하지 않습니다. 서버가 선점 뒤 실제 전송 전에 종료되거나 제공자 응답이 유실되면 해당 기기의 푸시가 누락될 수 있습니다. 알림함 기록은 유지합니다.
- HTTP 404/410 등 구독 만료 응답은 해당 기기 구독을 삭제합니다. 그 외 전송 실패도 자동 재시도하지 않고 실패 상태로 남깁니다.
- Web Push 외부 제공자는 idempotency key를 제공하지 않으므로 네트워크 응답 유실과 수신을 동시에 견디며 exactly-once 전송하는 것은 보장할 수 없습니다.

## 기술 구조 제안

- MongoDB 컬렉션: `push_subscriptions`, `notifications`, `push_deliveries`.
- FSD 엔티티: `src/entities/notification`에 알림 문서·조회·읽음 처리·전송 서비스, `src/features/notification`에 권한 요청·구독 관리 훅과 화면 흐름.
- Next.js API: 인증된 알림 목록/읽음 처리와 기기 구독 등록/해지, VAPID 공개 키 조회.
- PWA: 앱 매니페스트와 `public/sw.js`; 서비스 워커는 푸시를 표시하고 클릭 시 `/notifications`를 엽니다.
- 서버 라이브러리: `web-push`. 개인 키·subject는 서버 환경 변수 `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`에 저장하고, 공개 키는 인증이 필요 없는 읽기 전용 설정 응답으로 브라우저에 전달합니다.
- 최초 안내는 로그인된 `SiteHeader` 흐름에 연결합니다. 비로그인 랜덤 미리보기에는 나타나지 않습니다.
- Issue #10 동기화·결과 조정 유스케이스 뒤 최신 공개 회차의 알림함 항목을 upsert하고 활성 구독의 발송 이력을 선점·전송합니다. 알림함은 모든 회차 결과를 소급 생성하지 않고, 연결 시점의 최신 공개 회차부터 처리합니다.
- 사용자별 알림 응답과 TanStack Query 캐시는 `userId`를 포함한 키와 `private, no-store` API 응답으로 분리합니다.

## 아직 구현자가 정할 수 있는 항목

- 알림 목록의 첫 페이지 크기와 페이지 방식
- 알림 UI에서 읽음 처리 버튼과 항목 열람을 함께 처리할지 여부
- 브라우저별 저장소 키의 이름과 내부 모듈 배치
- VAPID subject 값 형식 및 개발·미리보기·운영별 키 입력 안내

## 수용 기준

- 사용자가 로그인 후 첫 브라우저 방문에서 안내를 보고, 거절 또는 보류해도 사이트 핵심 기능이 막히지 않습니다.
- 브라우저 권한 요청은 직접 클릭에서만 호출됩니다.
- 서로 다른 사용자 데이터가 API·MongoDB 조회·TanStack Query 캐시에서 섞이지 않습니다.
- 당첨 알림 생성, 회차 재조정, API 재시도는 알림과 발송 시도를 중복 생성하지 않습니다.
- 사용자는 구독한 현재 기기를 해지할 수 있고, 다른 기기의 구독은 그대로 유지됩니다.
- 로그아웃은 현재 기기의 구독만 해지하고 다른 기기의 구독을 유지합니다.
- 만료된 구독과 전송 실패가 기록·처리됩니다.
- 푸시 미지원·권한 거부·권한 미결정·등록 실패·빈 알림·조회 오류 상태가 구분됩니다.
- 모바일 PWA 설치 상태에서 구독, 푸시 표시, 푸시 클릭 이동을 검증합니다.

## 사용자에게 필요한 환경 변수

`.env.example`에는 이름만 기록하며 실제 값은 사용자가 Vercel에 설정합니다.

- `VAPID_PUBLIC_KEY`
- `VAPID_PRIVATE_KEY`
- `VAPID_SUBJECT`
